# ADR 0034：显式普通源前缀缺失恢复

- Status: accepted

## 背景

普通源的持久 outbox 可能保留后续原始签名段，而早期所需前缀已经无法找回。现有严格序号链会正确拒绝后续段，但容量保护因此持续暂停采集。

Ready 仓库之间的保留期恢复不能证明普通源的缺失原因，不能据此伪造 `source_retention_expired`。

源端保留的聚合还可能包含仓库已有样本的贡献。内容不同不表示贡献互斥；把它们加入原有聚合会重复计数。

## 决定

增加 root 操作的 `xp-ops xp history-prefix-recovery`。

此流程只处理当前注册源的 `runtime`、`traffic`、`path_health` 历史流，不自动推断不可恢复，不参与普通投递的周期性修复。

源端按显式计划只读导出：首个持久待发原始段、精确接收水位、该缺失序号区间仍保留的聚合记录，以及集群和目标仓库绑定。

源端还绑定持久删除版本，将完整删除意图签为独立的 tombstone 基线流。

仓库在同一事务中先应用该基线，再接受原始队列头。

该证明不清除源删除意图，也不替代正常删除 ACK。源身份对有域隔离的清单摘要签名。

仓库预览与提交均重新向源的注册公网 HTTPS 获取相同清单；改变身份、成员、地址、版本、删除状态、原始队列头或接收水位会使旧预览失效。

全部 voter 的签名同版本 preflight 和 leader quorum 校验沿用现有恢复门禁。

仓库提交必须有 `--apply --yes --expected-fingerprint`。

同一历史事务保存有界恢复证据、标记 `operator_confirmed_unrecoverable_prefix`，并接收未经重签的原始队列头。

证据是一次恢复世代的持久消费凭证，不能再次跨越新的缺口。失败不提交证据、缺失标记、接收水位或 ACK。

保留聚合进入独立的恢复证据账本，可由同一命令无文件参数时检查，不进入普通查询或 retention 聚合器，也不覆盖已有聚合。该账本保存源内容、来源签名及摘要、精确序号缺口；

已有删除保护会过滤导入内容，后续对应 tombstone 在同一事务清除证据副本。单 bundle 最多 8 个不同流、128 条记录、192 KiB；

总账本最多 32 次恢复且不超过 1 MiB，超限拒绝而非静默淘汰。

缺失原始段不能证明准确的观察时间边界，因此缺失时间范围保守覆盖恢复前的历史。历史继续报告 partial；不能以恢复上报成功宣称原始历史完整。

普通源不改 epoch、不删除 outbox、不产生本地假 ACK；后续由原有严格投递及真实接收回执排空队列。

## 代价与兼容性

证据提供可核查的保留原内容，但不作为第二份可相加的统计来源。若未来要合并互相重叠的聚合，需要独立的贡献证明，不能用序号包络或较大 record_count 假定包含关系。

各部署形式共享同一持久数据目录和实现。升级必须保留 history.sqlite3。没有此证据字段的旧版本不能安全维护恢复后的账本，不允许部署覆盖。恢复功能不改变仓库成员，不授权把普通源临时加入仓库。

保留聚合另有逐条域隔离的源签名，绑定原清单摘要与完整记录内容。

重启后只凭持久证据即可验签；删除只移除对应记录和证明，剩余记录仍可独立核验。

完整删除基线在遍历阶段限制记录数及内存预算；超限失败，不把部分基线标记为完整。
