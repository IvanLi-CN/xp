# ADR 0032：恢复旧身份原始历史与源端 ACK

## 状态

已采纳。实现通过资源门禁和受限生产候选验证；后续修改仍须验证其对应提交。

## 背景

节点换身份后，原始 outbox 仍可能保留旧身份签名的数据。

普通上报要求发送者与当前成员身份匹配，不能为恢复而放宽此约束。

原有历史修复事务没有对外返回逐段收据，无法闭合源端队列清理。

## 决定

提供仅由本机身份签名调用的两阶段运维操作，作为长期支持的旧身份队列恢复能力。

操作端只编排正式 CLI；服务端负责校验、事务与真实 ACK，断开后从持久队列重新预览恢复，不依赖特定节点名或临时脚本保存正确性。

`history-original-source` 从源端自身持久队列预览最多 32 段、1 MiB 原始 wire。

`history-original-import` 仅在 Ready 仓库接收已离开集群的原始来源身份。

导入须验证来源派生身份、原始签名、严格序号及哈希链，并保留现有删除语义。

所有 voter 的签名公网预检、相同版本及 leader quorum 验证继续适用。

预览不写数据；提交需 `--apply --yes --expected-fingerprint`。

指纹绑定原始页、目标、接收进度及集群视图；事实变化即拒绝。

导入页在单个历史事务成功提交后才返回全部收据。

不接受缺口声明，不修改原始 wire，不生成永久缺口或重置成员身份。

源端清理不接受操作端转述的收据。

它通过已注册仓库的公网 HTTPS 发起签名查询，验证真实 ACK，

并要求每个原始 wire 的哈希均已持久保存且处于已验证的接收链中。

核验后重新检查集群与本地页未变化，才调用现有原子 ACK 事务。

新身份采集必须等待旧队列、背压与删除映射全部清空。

满足条件后分配独立 epoch，从新身份的零序号开始。

不能把旧身份的序号或哈希链续接到新身份。

## 部署与限制

systemd、OpenRC 与单镜像容器使用同一实现。

容器无 xp.env 时显式传入 `--data-dir /var/lib/xp/data`。

源端与接收仓库均须部署通过资源门禁的候选，再运行正式 CLI。

本决定不授权新仓库成员、缺失原始 wire 的跨缺口恢复或直接修改 SQLite。
