# ADR 0033：服务就绪后的备份清理提交边界

## 状态

已采纳。

## 背景

整份读取事务备份会使低内存节点在正式升级收尾 OOM。仅以文件描述符代替内存副本，
仍不能保证多文件 unlink 的回滚：后续删除及恢复同时失败时，已经 unlink 的旧 inode
会随进程退出消失。为恢复而额外复制全部备份也违反低磁盘部署约束。

## 决定

服务激活、所需就绪检查与其他 artifact 清理全部完成后，备份删除成为提交后的清理阶段。
在第一个 unlink 前，持久化并同步既有、有界的 diagnostics.json 清理守卫；守卫失败时，
备份尚未删除，继续原有回滚路径。

提交后的备份清理只校验普通文件身份并逐个 unlink，不读取二进制内容，也不创建恢复副本。
此时删除失败不再回滚已经就绪的新程序；返回 cleanup_incomplete: committed_upgrade，
报告失败终态并保留未删除的事务备份及诊断。下一次升级在这些备份仍存在时拒绝开始，
由 root 核验当前正式程序、服务就绪与剩余备份后完成精确清理。守卫也覆盖进程意外退出。

在提交边界之前发生的安装、配置、服务激活或就绪失败仍按既有契约回滚；
无法恢复的事务备份继续受 rollback_failed 保护。

成功终态仍要求零事务备份，并移除诊断；清理失败不得伪装成功。
这适用于 systemd 和 OpenRC 的共同 host-managed 路径，不改变容器镜像替换方式。

## 后果

内存不随备份体积增加，提交后的磁盘故障不再触发不可能完成的多文件回滚。
运维必须区分服务激活失败与服务已就绪但清理未完成，不能依据非零退出码擅自降级。
