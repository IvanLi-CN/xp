# Mihomo resource mirror boundary

XP 显式镜像模式按需代取 Geo 数据、规则集和代理集，只接纳固定 GeoX 资产和 profile 当前引用的 HTTPS 地址。客户端可在代理建立前下载，XP 不提供任意 URL 代理或缓存。

镜像采用集群密钥派生的 HMAC 资源 ID，按目录准入，持有地址即可访问；不绑定订阅 token 或短期有效期。这保持客户端长期更新可用，避免资源下载依赖 token 轮换或签名续期。

## Consequences

- 资源地址可转发给他人；HMAC 隐藏原 URL，但不验证调用者身份，也不提供每个订阅的撤销语义。
- 自定义资源在最后一个 profile 引用移除后拒绝新请求；固定 GeoX 资产持续可用。
- 相同集群密钥与规范化原 URL 产生相同资源 ID，多个 profile 可共享资源地址。
- 无缓存保证内容来自每次请求的上游；可用性取决于服务节点与上游，订阅生成不预检上游。
- 接受带查询参数的 HTTPS 原 URL；查询参数可能含上游凭据，分享镜像地址也会分享相应内容访问权。
- 私网目标继续由节点本地 CIDR 策略授权；公开资源地址不授予配置策略或选择任意上游的权限。

## Considered Options

- 订阅 token 绑定：提供独立撤销，但会改变现有共享资源地址和目录模型。
- 短期签名：缩短泄露后的访问窗口，但长期持有配置的 Mihomo 可能无法继续更新 Geo 数据。
- 内容缓存：降低重复下载成本，但引入存储、失效和陈旧内容语义。
- 任意 URL 代理：使用更自由，但突破订阅资源目录的目标准入边界。
